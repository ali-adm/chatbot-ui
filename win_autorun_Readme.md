NSSM расшифровывается как **Non-Sucking Service Manager**. Это инструмент, который позволяет превратить любое приложение или скрипт в сервис Windows, что позволяет запускать их автоматически при старте системы. NSSM считается удобным инструментом для работы с сервисами, особенно когда стандартные средства Windows не подходят.

### Настройка автозапуска через NSSM

Вот пошаговое руководство по настройке вашего Node.js приложения (или любого другого) в качестве сервиса с использованием NSSM:

#### Шаг 1: Загрузить и установить NSSM

1. Перейдите на [официальный сайт NSSM](https://nssm.cc/download) и скачайте соответствующую версию для вашей архитектуры системы (x86 или x64).

2. Распакуйте архив в удобное место, например, `C:\nssm`.

#### Шаг 2: Использовать NSSM для создания сервиса

1. Откройте командную строку от имени администратора.

2. Перейдите в директорию, где вы распаковали NSSM. Например:

   ```bash
   cd C:\nssm\win64
   ```

3. Выполните команду для установки нового сервиса:

   ```bash
   nssm install ChatbotUI
   ```

4. Появится окно настройки нового сервиса. Заполните поля следующим образом:

   - **Application Path**: Укажите полный путь к вашей `node.exe` (например, `C:\Program Files\nodejs\node.exe`).
  
   - **Startup Directory**: Укажите директорию вашего проекта.
  
   - **Arguments**: Укажите команду для выполнения, обычно это `C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js run dev`.

#### Шаг 3: Настроить дополнительные параметры (опционально)

- На вкладке **Details** можно указать описание сервиса.
- На вкладке **Log on** можно выбрать, под какой учетной записью запускать сервис. По умолчанию это `Local System Account`.

#### Шаг 4: Запустить сервис

После настройки всех параметров нажмите "Install Service". После установки вы можете управлять сервисом с помощью команд:

- Запуск сервиса: 

  ```bash
  nssm start ChatbotUI
  ```

- Остановка сервиса:

  ```bash
  nssm stop ChatbotUI
  ```

- Открыть окно настройки сервиса:
  ```bash
  nssm edit ChatbotUI
  ```

- Удаление сервиса:

  ```bash
  nssm remove ChatbotUI
  ```

### Преимущества использования NSSM

- **Надежность**: Приложение перезапускается, если оно упало.
- **Удобство**: Легкое управление через интерфейс Windows для служб.
- **Гибкость**: Возможность установки любых приложений как сервисов.

Используя NSSM, вы сможете легко организовать автозапуск вашего Node.js приложения при старте Windows и не беспокоиться о том, что нужно будет вручную запускать его каждый раз. 
---

Если служба приостанавливается и перезапускается, это обычно свидетельствует о том, что возникла ошибка при запуске приложения. Возвратный код `1` часто означает общую ошибку. Давайте попробуем диагностировать проблему и решить её:

### Возможные причины и решения

1. **Ошибки в коде приложения или его конфигурации**:

   - Убедись, что код приложения, которое ты запускаешь, работает без ошибок. Может быть полезно запустить команду `npm run dev` вручную из командной строки, чтобы выяснить, нет ли явных ошибок.

2. **Проблемы с конфигурацией NSSM**:

   - Дважды проверь, что пути, указанные в параметрах NSSM, корректны.
   - Проверь `Startup directory`: убедись, что путь `E:\Work\UPSAssistant\UPSAssist\perchat\chatbot-ui` действительно содержит файл `package.json`, в котором прописан скрипт `dev`.

3. **Зависимости и окружение**:

   - Убедись, что все зависимости установлены. Ты можешь попробовать переустановить их, запустив команду `npm install` в директории проекта.
   - Убедись, что `node` и `npm` находятся в переменной окружения `PATH`. Попробуй выполнить следующее и убедись, что команды выполняются без ошибок:
     ```bash
     node -v
     npm -v
     ```

4. **Проверка логов**:

   - Добавьте настройку логирования в NSSM для вашего сервиса, чтобы записывать выходные данные `stdout` и `stderr` в файлы. Это может помочь лучше понять, какая ошибка происходит:
     - В NSSM, в настройках вашего сервиса, перейдите на вкладку *I/O*.
     - Укажите файлы для стандартного вывода и стандартного вывода ошибок — например, `stdout.log` и `stderr.log`.
     - Это может помочь в диагностике, показав точные ошибки, выводимые приложением.

5. **Редактирование скриптов**:

   - Попробуй запустить минимально необходимый скрипт через `node`, убрав `npm-cli.js`, если это возможно. Бывает, что запуск npm скрипта напрямую через `nssm` вызывает сложности.

Вот пример, если ты хочешь запустить напрямую JavaScript файл:

```bash
nssm install ChatbotUI "C:\Program Files\nodejs\node.exe" "app.js"
```
---

Когда вы запускаете команды с пробелами в пути в Windows, лучше всего обрамлять каждый компонент пути в кавычки.

### Исправление проблемы с путями NSSM

1. Откроем настройки вашего сервиса для редактирования:

   Запускаем команду в командной строке от имени администратора:
   
   ```bash
   nssm edit ChatbotUI
   ```

2. Убедитесь, что пути правильно обрамлены в кавычки:

   - **Application Path**: `"C:\Program Files\nodejs\node.exe"`
   - **Arguments**: `"C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js" run dev`

   Обратите внимание, что каждый компонент, включая сам путь до `npm-cli.js`, включен в кавычки.

3. **Запуск директории**: не забудьте также указать корректный путь до вашей рабочей директории. Убедитесь, что он также обрамлён в кавычки, если содержит пробелы. Например:
   
   - `"E:\Work\UPSAssistant\UPSAssist\perchat\chatbot-ui"`

### Альтернативное решение

Если проблема все равно сохраняется, попробуйте создать дополнительный `.bat` или `.cmd` файл для запуска вашего приложения и используйте NSSM для запуска этого батника:

1. Создайте новый файл, например `start-script.cmd`, в рабочей директории с содержимым:

   ```bat
   @echo off
   cd /d "E:\Work\UPSAssistant\UPSAssist\perchat\chatbot-ui"
   "C:\Program Files\nodejs\node.exe" "C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js" run dev
   ```

2. Настройте NSSM для запуска этого скрипта:

   - **Application Path**: путь до `cmd.exe` (например, `C:\Windows\System32\cmd.exe`).
   - **Arguments**: `/c "E:\Work\UPSAssistant\UPSAssist\perchat\chatbot-ui\start-script.cmd"`

Если вы выполните эти шаги, вы избегаете проблем, связанных с интерпретацией путей.
